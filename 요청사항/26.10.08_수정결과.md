## 작업 1. 사진 업로드 · Vision AI 읽기 복구

### 원인
공유 링크 배포본이 **AI 키가 비어 있는 상태로 빌드**되어 있었습니다. 키가 없으면 앱이 "데모 모드"로 돌면서 사진 버튼을 숨기고 "Photo reading is not available"만 띄웁니다. 코드 버그가 아니라 빌드 환경 문제였습니다.

### 조치
| 항목 | 내용 |
|---|---|
| 키 폴백 | 빌드에 키가 없어도 시연 기기에 키를 한 번 넣으면 사진 읽기가 켜지도록 함. "받은 문서 찍기" 화면 하단 **"AI 키 넣고 사진 읽기 켜기"** 버튼 → 키 붙여넣기 → 새로고침. 키는 그 기기 브라우저에만 저장됨 |
| 추출 항목 확대 | AI 프롬프트가 **금액·납기·전자납부번호·가상계좌번호**를 읽도록 변경. 이름·주소·주민/외국인등록번호·납세번호·차량번호는 계속 읽지 않음 |
| 확인 화면 | 전자납부번호·가상계좌 입력칸 추가. AI가 잘못 읽으면 사용자가 고칠 수 있음 |
| 샘플 고지서 | 테스트 고지서 기준으로 교체: 143,000원 · 전자납부번호 1163-0202-6120-0043-21 · 가상계좌(가상) 행 추가. 87,500원 하드코딩 제거 |

### 배포 전 필요한 일
- 키가 든 `.env`로 `npm run build`를 다시 돌려 배포본을 올려야 공유 링크에서 바로 사진 버튼이 보입니다. 그 전까지는 위 "AI 키 넣기" 버튼으로 시연 가능합니다.
- 실제 143,000원 테스트 이미지는 저장소에 없어 **샘플 고지서로만 흐름을 검증**했습니다. 실물 이미지로 한 번 돌려보고 전자납부번호·가상계좌가 맞게 나오는지 확인 부탁드립니다.

## 작업 4. 구현 현황 확인

### ① 전자납부번호 처리 위치
**기기 내부에서만 끝나지 않습니다.** 흐름은 다음과 같습니다.

1. 사진은 기기에서 개인정보 영역을 검게 가림 (`src/utils/sampleNotice.ts` maskCanvas)
2. **가린 이미지**를 Google Gemini API(generativelanguage.googleapis.com)로 전송 (`src/services/ai.ts`)
3. Gemini가 돌려준 JSON(금액·납기·전자납부번호·가상계좌)을 앱 메모리(React 상태, `src/context/DocContext.tsx`)에만 보관

즉 번호를 "읽는" 주체는 Google 서버이고, 그 뒤로는 기기 메모리에서 끝납니다. 자체 서버는 없고, 브라우저 저장소(localStorage)에도 저장하지 않으며, 복사 버튼은 기기 클립보드만 씁니다. 운영 시에는 서버 프록시를 두어야 한다는 점은 README에 명시되어 있습니다.

### ② 시연 기기 기능
| 기능 | 결과 | 비고 |
|---|---|---|
| 음성 안내 | **동작** | 할 일 카드 "읽어주기" 버튼 → 브라우저 내장 음성(speechSynthesis), 언어별 음성 지정. 네팔어는 기기에 음성 엔진이 없으면 소리 없이 끝남 |
| 큰 글씨 | **동작** | 상단 "큰 글씨" 칩 → 전역 글자 크기 1.18배. 새로고침하면 초기 크기로 돌아감 (저장 안 함) |
